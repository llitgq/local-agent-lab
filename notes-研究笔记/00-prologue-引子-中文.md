# 📝 00 · 引子：两年，从对话框走到智能体

[English](00-prologue-引子.md)

> 这不是教程，是我两年折腾的流水账。如果你也在这条路上，希望能帮你少走一点我走过的弯路。
>
> 2026-10-30

## 🌱 背景：从埋怨 AI 开始

GPT 上市之后，我就一直泡在对话式 AI 里。最早的阶段其实挺苦恼的——埋怨 AI 的种种限制，埋怨它没法真正帮我做事。后来去研究了一下"提示词"这个东西，看了些课、刷了些视频，才算摸到一点门。

## 🐣 第一阶段：想到啥问啥

小白时期的用法：一句话扔过去，AI 就输出。答案不能说没用，但**太浅了**，基本满足不了我的要求。

## 📏 第二阶段：学会写要求

学了之后才知道要把**任务边界**写清楚：做什么、不做什么，输出什么、不输出什么，加上各种约束和限定，也学了一些术语。同样的模型，问法一变，质量立刻不一样。

## 🧱 第三阶段：结构化提示词

再往后进阶到**结构化提示词**：套用角色 + 背景上下文 + 约束 + 输出格式。说实话，本质上跟上一步没什么区别——只是做得更细致了。每次写之前先建一个梗概，再往里填。我常用的就是 `Task / 背景 / 输出` 这种风格，也就是所谓的 personal prompting。

## 🧠 第四阶段：控制上下文

然后是**上下文工程**：在对话的往复论述里，一步步控制上下文——哪些该保留、哪些直接扔掉，节省模型的"记忆空间"。再加上思维链（让它一步步拆解推导再给答案）、思维树这些玩法。到这个阶段，效率已经比一开始的一问一答**拉开了很大很大的差距**。我个人感觉，光到这里，产出就已经翻了几倍。

## 🤖 第五阶段：智能体，转不过来的那道坎

真正的大坎出现在 **OpenClaw 刚上线**的时候。

我的强项本来是把整个流程写得特别规范——这是提示词时代攒下的功底。但到了智能体时代，突然转不过来了：以前的 AI 是对话式的，现在要把它的**身份定义拆成无数个零件**；以前 AI 不能操作电脑，只能做文字、视频这些，真正的工作流靠人工、靠脚本、靠影刀这类 RPA 工具一点点拼起来。现在它**真的可以自己做了，但做得很 low**。

我给了它完整的规范，希望它聪明、做事干净利落、不把任务推回给我——但就是做不到，没法真正有意义地完成任务和工作流。后来我才明白：不是把事情想窄了，而是**对话式 AI 用多了，思维把自己限制住了**，根本不懂怎么写智能体的身份定义。这一道坎，卡了我差不多一到两周。

## 🌀 第六阶段：越用越傻，与 `/new` 的顿悟

过了坎也不是一帆风顺。无数次重装、研究、再重装、再研究。然后撞上另一个问题：**一个 Agent 越用越傻**。因为上下文越积越多。于是去研究多 Agent——结果每个 Agent 的上下文也不小，还是越用越傻。

被逼无奈，我给 OpenClaw 做了一堆辅助工具和辅助智能体：管上下文的、串提示链的、搭工作流的。而**最重要的一个发现，是 `/new`**——新开一个窗口，干干净净地重新开始。说来好笑，如果我从一开始就用 Claude Code 这种对话窗口式的工具，可能早就明白这个道理了，但当时就是没转过弯。

## 🕊️ 现在：一个和平的分工

到今天，我把 OpenClaw、Hermes 和 Claude Code 揉在了一起，形成了一个相对和平的状态：

- ✍️ **写 Skill、定义流程** → 用 Claude Code
- ⚙️ **执行工作流、跑定时任务、日常对话** → 交给能外延连接飞书的智能体（OpenClaw / Hermes）
- 💼 **自己真正的办公产出** → 还是 Claude Code

## 🔜 下期预告

这一篇只是引子，讲讲这两年我是怎么折腾过来的。从下一篇开始，我会真正地回头拆解：**如果从零开始走这条路，前几步应该怎么迈，才能把成本省到最小、效果拿到最好。**
